# Hekili Midnight: гибридный помощник ротации для WoW 12.x

**Дата:** 2026-09-07 · **Ветка:** `midnight` · **Форк:** https://github.com/asilak/hekili

## Цель

Сделать аддон работоспособным на актуальной версии игры (Midnight, 12.x).
Оригинальный проект закрыт 2026-01-20: собственный APL-движок Hekili требует чтения
боевых данных, которые в 12.0 стали **secret values** и недоступны Lua-логике аддонов
намеренно, по дизайну Blizzard. Легального обхода нет.

## Выбранный подход (решения пользователя)

1. **Гибрид**: база рекомендаций — встроенный движок Blizzard
   (`C_AssistedCombat.GetNextCastSpell()`), поверх — собственный слой поправок
   на данных, оставшихся читаемыми (стиль TrueShot).
2. **Охват поправок**: паладин целиком — Holy, Protection, Retribution.
   База от Blizzard при этом работает для всех спеков автоматически.
3. **Оболочка**: поэтапно — сначала тонкий новый каркас без легаси, элементы UX
   Hekili (тогглы, стили дисплеев, панель настроек) переносятся позже по мере ценности.

## Ограничения платформы 12.x (фактическая база)

Читаемо в бою (на этом строим поправки):
- вторичные ресурсы игрока (Holy Power, комбо-очки, руны и т.п.);
- проценты здоровья/ресурса: `UnitHealthPercent`, `UnitPowerPercent`;
- ID экземпляров аур и количество стеков (глубина — проверить в клиенте);
- проверка дальности, классификация заклинаний;
- `C_RestrictedActions`, `C_Secrets` — интроспекция активных ограничений.

Засекречено (не используем): всё о враге, лог боя (удалён), абсолютные значения
первичных ресурсов, собственные касты в бою.

## Архитектура

Новая папка `Midnight/`, загружается через `Hekili.toc` (Interface → 12.x).
Легаси-движок (`State.lua`, `Scripts.lua`, `Core.lua`, спек-файлы, `Options/`)
исключается из загрузки, остаётся в дереве как справочник spell ID.
Этап 1 — **без Ace3** (локально `Libs/` пуст, внешние библиотеки доступны только
при пакетировании): чистые фреймы, тестирование через симлинк + `/reload`.

| Модуль | Ответственность |
|---|---|
| `Midnight/Engine.lua` | Опрос `GetNextCastSpell()` (события + троттлинг OnUpdate), очередь «текущая + следующая», рассылка подписчикам |
| `Midnight/Corrections.lua` | Конвейер правил per-spec: предикат над читаемыми данными → замена/аннотация рекомендации; регистрация правил, порядок, включение/выключение |
| `Midnight/Paladin.lua` | Правила трёх спеков паладина; spell ID из `TheWarWithin/Paladin*.lua`. Примеры: Holy Power = 5 → финишер; HP < 35% → Word of Glory / защитный |
| `Midnight/Display.lua` | Очередь иконок в духе Hekili (текстуры из `Textures/`), кейбинды на иконках, перемещение/масштаб, `SavedVariables: HekiliMidnightDB` |

## Обработка ошибок

- **Fail-open**: любая ошибка/secret-taint в слое поправок → молча отдать чистую
  рекомендацию Blizzard. Всё потенциально секретное — через pcall-обёртки.
- При активных ограничениях (`C_RestrictedActions`) слой поправок отключается сам.
- Аддон не должен генерировать Lua-ошибок в бою ни при каких условиях.

## Этапы

1. **Каркас**: TOC 12.x, Engine + Display, база Blizzard для всех спеков. Критерий:
   загружается без ошибок, очередь отображается, иконки соответствуют ассистенту.
2. **Поправки паладина**: Corrections + Paladin, три спека. Критерий: правила
   срабатывают на манекене, при ошибках — деградация без Lua-ошибок.
3. **UX** (после рабочих 1–2): тогглы кулдаунов/защитных, стили дисплеев,
   перенос нужных частей панели настроек.

## Проверка

Автотестов нет (в проекте их не было; игровой клиент не автоматизируется):
`luacheck` статически + ручной чек-лист в игре на каждый этап (готовит Claude,
выполняет пользователь): загрузка → отображение → срабатывание правил → инстанс
без ошибок.

## Риски

- Точная граница «что читаемо» (особенно ауры) подтверждается только эмпирически
  в клиенте — правила писать защитно.
- Blizzard регулярно меняет API 12.x — слой поправок сознательно мал и изолирован,
  чтобы поломки были дёшевы.
- Прецедент TrueShot (аналогичный гибрид) уже исчез с GitHub — не полагаться на
  чужие реализации, только на официальные API.
